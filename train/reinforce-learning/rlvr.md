# RLVR

### 1 什么是 Verifiable Reward

一个奖励函数 $$r(q, o)$$ 如果可以由一段确定性程序在有限时间内判定，就称为 verifiable reward。最常见的形式是二值的:

$$r(q, o) = \mathbb{1}\{\mathrm{verify}(q, o) = \texttt{pass}\} \in {0, 1}$$

其中，`1{...}` 是**指示函数,**&#x547D;题为真返回 1,为假返回 0:

典型实例:

| 类型     | 验证器                    |
| ------ | ---------------------- |
| 数学最终答案 | 字符串/数值/符号等价匹配          |
| 代码     | 解释器 + 单元测试             |
| 形式化证明  | Lean / Coq 内核          |
| 结构约束   | JSON Schema、正则、长度、格式标签 |
| 游戏/规划  | 环境模拟器的终止状态             |

它的三个关键性质:

* **可判定**:有固定的标准。
* **廉价且可并行**
* **相对抗操纵**: “相对”不那么容易被 hack

**可验证性是关于"评价"的性质,不是关于"任务"的性质**。同一个任务，换一种输出格式，可验证性会完全不同。

### 2. 为什么数学和代码最适合 RLVR

三个原因：

1. **生成难、验证易的不对称性。** 这本质上是 NP 式的结构：找到一个 15 行的正确实现很难，运行 20 个单元测试很容易。RL 需要海量的 $$(o, r)$$ 对，只有当验证成本远低于生成成本时，这个循环才在经济上成立。
2. **答案空间可归一化。** 数学题的最终答案能被投影到一个小的、可比较的空间(例如一个整数、一个分式、一个表达式)。这让"对/错"这个判断不需要理解中间推理。
3. **语义由执行定义。** 代码尤其特殊:它的正确性不是由人的判断定义的，而是由解释器定义的。这意味着奖励几乎没有标注噪声，也就是不存在主观性。

反过来说，这三个理由也精确地指出了 RLVR 在别处会遇到什么困难：开放式写作的输出空间不可归一化，长程 agent 任务的验证成本可能高于生成成本，而"这个回答有帮助吗"没有执行语义。

但是实践并没有想象中那么简单，中数学 RLVR 的验证器有大量**假阴性**(例如`1/2` vs `0.5` vs $$\frac{1}{2}$$； $$2\sqrt{3}$$ vs  $$\sqrt{12}$$ )和**假阳性**(多选题猜中、数值巧合、模型输出里恰好包含答案子串)。一个粗糙的 `boxed` 正则匹配，假阴率能到百分之几——这些噪声会被后面讲的方差放大机制放大。

### 3. RLHF、RLAIF、RLVR 的区别

|        | RLHF                              | RLAIF                     | RLVR            |
| ------ | --------------------------------- | ------------------------- | --------------- |
| 奖励来源   | 人类偏好数据训练的 RM                      | 更强 LLM 的判断 / constitution | 确定性程序           |
| 信号形式   | 标量(有序但无绝对尺度)                      | 标量或偏好                     | 二值(或分档)         |
| 标注成本   | 高,随任务线性增长                         | 中,可扩展                     | 近乎没有            |
| 主要失效模式 | RM over-optimization(奖励模型被外推到分布外) | judge 的风格偏好、自我偏爱、谄媚       | 验证器漏洞、格式钻空、答案泄漏 |
| 优化上限   | RM 的准确性                           | judge 的能力                 | 验证器的覆盖度         |
| 适用任务   | 主观、开放                             | 主观 + 半客观                  | 客观、可判定          |

RLHF、RLAIF、RLVR 三者的**差别不在算法，真正的区别在于谁来当裁判**。

* **RLHF：**&#x88C1;判是人。但人打分又慢又贵，所以实际做法是先请人打少量一批分数，再根据这批数据训一个小的 Reward Model。
* **RLAIF：**&#x88C1;判是另一个 LLM，给它一份评分标准,让它照着打。
* **RLVR：**&#x88C1;判是一段程序。代码就跑测试，数学就对答案,对了给 1,错了给 0。

GRPO/PPO 都可以配任意一种奖励。RLVR 的独特优势是 oracle 的**保真度上限是 1.0** 而不是 RM 的 0.7\~0.9;它的代价是 oracle 的**覆盖率极低**——世界上大部分值得做的任务都不在它的定义域里。

还有一个常被忽略的差别:RLHF 的奖励通常是**稠密相对**的(任何两个回答都能比出高低),而 RLVR 的奖励是**稀疏绝对**的(要么 0 要么 1)。这直接导致了后面所有关于组内方差、零梯度、采样效率的问题。

### 4. Outcome Reward 与 Process Reward

**Outcome Reward (ORM)**:只在序列末尾给一个信号,$r$ 只依赖最终答案。 **Process Reward (PRM)**:给推理链的每一步 $s\_i$ 一个信号 $r\_i$。

差别的本质是 **credit assignment(信用分配)**。一条 500 token 的推理链只拿到一个 bit 的反馈,意味着策略梯度必须把这 1 bit 均摊到 500 个 token 上——第 300 步的关键错误和第 5 步无关紧要的措辞得到完全相同的惩罚。这是纯粹的统计效率问题,需要更多样本才能把有效信号从噪声里分离出来。

#### 4.1 结果奖励真的改善了推理过程吗?

这是本文最想认真回答的问题。答案是:**它可靠地改善了"拿到正确答案的策略",只在推理是拿到答案的必要手段时才顺带改善推理**。三类证据:

**(a) 分布锐化 vs 能力扩展。** 大量复现实验观察到同一个模式:RLVR 之后 pass@1 显著上升,而 pass@k(k 较大,比如 256)持平甚至下降。这个现象的解读是:RL 把 base model 本来就能采样到的正确解的概率质量往上抬,同时压缩了熵——它重新分配了概率,而没有创造新的解。这个结论有争议(更长训练、更难数据、更大 k 上有相反的报告),但作为默认假设它是稳健的:**GRPO 的更新方向永远是"把已经成功过的东西做得更确定",它结构上无法奖励一个从未成功过的行为**。第 5 节的数学会让这一点变得非常明确。

**(b) 答案对但过程错。** 结果奖励对"歪打正着"完全无感。多选题、有限答案空间的数值题、以及模型在错误推理后凭直觉写出正确答案的情况,都会拿到 $r=1$。ProcessBench 一类的评测显示,即使是很强的模型也难以定位一条推理链里第一个出错的步骤——这说明"过程正确性"和"答案正确性"在训练信号层面被系统性地混同了。更糟的是,有研究观察到 outcome-only RL 会**降低**推理链的忠实度(faithfulness):模型学会写出一段看起来像推理的文本,同时用另一条内部捷径得到答案。

**(c) Spurious reward。** 有工作报告过:对某些 base model(尤其 Qwen 系),即使用随机奖励或错误奖励做 RL,某些数学 benchmark 上的分数也会上升。这几乎只能解释为 RL 在**唤醒**预训练里已有的格式与行为模式(输出 `\boxed{}`、使用代码式推理),而不是在**学习**推理。这对"结果奖励改善了推理"是相当严厉的反证。

**结论**:结果奖励是一个关于**输出端点**的约束。凡是存在捷径的地方,它就会奖励捷径;凡是推理是唯一路径的地方,它才奖励推理。所以"能不能靠结果奖励得到好的过程"这个问题,等价于"任务是否已经封死了所有捷径"——而这是数据设计问题,不是算法问题。

### 5. GRPO 在 RLVR 中扮演什么角色

#### 5.1 算法本体

GRPO 相对 PPO 的唯一实质改动:**用组内蒙特卡洛统计量替代 critic**。对每个 prompt $q$ 采 $G$ 条回答 ${o\_1,\dots,o\_G}$,优势为白化后的奖励:

\$$A(q, o\_i) = \frac{r(q,o\_i) - \mu(q)}{\sigma(q)}, \quad \mu = \frac{1}{G}\sum\_j r\_j,\ \ \sigma = \mathrm{std}(r\_{1..G})\$$

目标函数是 PPO 式的裁剪代理目标,加上对参考策略的 KL 惩罚。省掉 critic 带来两个好处:显存减半、以及不需要处理"critic 在长序列上估不准价值"这个老问题。

#### 5.2 为什么能放大成功概率:精确的形式

设 $p(q)$ 为旧策略在问题 $q$ 上的成功概率(PoS, probability of success)。奖励是伯努利的,所以 $\mu = p$,$\sigma^2 = p(1-p)$。代入白化公式:

\$$A(q,o) = \begin{cases} \dfrac{1-p}{\sqrt{p(1-p)\}} = \sqrt{\dfrac{1-p}{p\}} & r = 1 \\\[2ex] -\dfrac{p}{\sqrt{p(1-p)\}} = -\sqrt{\dfrac{p}{1-p\}} & r = 0\end{cases}\$$

这个简单代换是理解 GRPO 的钥匙。它说明:**GRPO 不是在优化一个固定的奖励,而是在优化一个被"当前难度"重新标定过的奖励**。看具体数值:

| $p$  | 成功样本权重 $\sqrt{(1-p)/p}$ | 失败样本权重 $-\sqrt{p/(1-p)}$ |
| ---- | ----------------------- | ------------------------ |
| 0.01 | **+9.95**               | −0.10                    |
| 0.10 | +3.00                   | −0.33                    |
| 0.25 | +1.73                   | −0.58                    |
| 0.50 | +1.00                   | −1.00                    |
| 0.75 | +0.58                   | −1.73                    |
| 0.90 | +0.33                   | −3.00                    |
| 0.99 | +0.10                   | **−9.95**                |

读法:

* **难题上罕见的成功被极度放大**($p=0.01$ 时权重接近 10),而失败几乎不被惩罚。这就是"放大成功概率"的微观机制——它是一个自动的、免调参的**难度加权课程**。
* **简单题上失败被极度惩罚**,成功几乎不给奖励。GRPO 会花大量梯度去"堵住"那些本该做对却做错的题。
* 展开成损失函数,GRPO 等价于一个**自适应加权的对比损失**:正样本项的权重是 $\sqrt{(1-p)/p}$,负样本项的权重是 $\sqrt{p/(1-p)}$,而对比样本来自上一轮策略自己生成的合成数据。这是 ICML 2026 那篇文章的核心观察之一。

#### 5.3 成功概率的演化:一个不动点递推

在理想化设定下(去掉裁剪,只保留对 $\pi\_{\mathrm{ref\}}$ 的 KL 惩罚,强度 $\beta$),KL 正则化问题有闭式解 $\pi\_n \propto \pi\_{\mathrm{ref\}} \exp(A\_{n-1}/\beta)$。因为二值奖励下 $A$ 只取两个值,可以直接把它写成 PoS 的递推。用 logit 记 $\ell(x) = \log\frac{x}{1-x}$:

\$$\boxed{\ \ell(p\_n) = \ell(p\_{\mathrm{ref\}}) + \frac{1}{\beta,\sqrt{p\_{n-1}(1-p\_{n-1})\}}\ }\$$

(推导:成功与失败两个优势值之差为 $\sqrt{\frac{1-p}{p\}} + \sqrt{\frac{p}{1-p\}} = \frac{1}{\sqrt{p(1-p)\}}$,而 KL 正则解正是把这个差值除以 $\beta$ 加到参考策略的对数几率上。)

这个式子把几件事一次讲清楚了:

1. **成功放大是结构性的,不是经验性的。** 增量项 $\frac{1}{\beta\sigma}$ 恒为正,所以每一步都有 $p\_n > p\_{\mathrm{ref\}}$。迭代收敛到不动点 $p^\ast$,满足 $\ell(p^\ast) = \ell(p\_{\mathrm{ref\}}) + \frac{1}{\beta\sigma^\ast}$,因此 $p^\ast > p\_{\mathrm{ref\}}$ 恒成立。这正是 ICML 2026 那篇文章证明的 success amplification。
2. **放大幅度有下界。** 因为 $\sigma = \sqrt{p(1-p)} \le 1/2$,所以增量 $\ge 2/\beta$。即 $\ell(p^\ast) \ge \ell(p\_{\mathrm{ref\}}) + 2/\beta$。$\beta \to 0$ 时 $p^\ast \to 1$。
3. **KL 强度是天花板旋钮,不是稳定性旋钮。** $\beta$ 唯一地决定了能爬多高。这在数学上解释了为什么 DAPO 等大规模系统直接去掉对参考模型的 KL 之后天花板会上升——以及为什么代价是策略可以任意漂移(语言混杂、长度爆炸、行为退化)。KL 到 $\pi\_{\mathrm{ref\}}$ 提供的是一个**恢复力**,不是一个**信任域**;信任域是 clip 和 mirror 项(KL 到 $\pi\_{n-1}$)的职责。三者应该分开讨论——ICML 2026 那篇正是按 mirror / reference / mixed 三种正则化分别给出了各自的 PoS 递推。
4. **$p \to 0$ 时递推失效。** 增量项 $\frac{1}{\beta\sqrt{p\}}$ 形式上会爆炸,但这是理想化连续分析的产物。有限 $G$ 下,$p$ 的估计量是 $\hat p = k/G$,当 $k=0$ 时 $\sigma=0$,优势是 $0/0$,实现里被置零。所以真实的放大倍数是

\$$\text{amplification} \approx \min\left(\frac{1}{\sqrt{p(1-p)\}},\ \sqrt{G-1}\right)\$$

——在 $p \gtrsim 1/G$ 时由难度决定,在 $p \lesssim 1/G$ 时被组规模**截断**($k=1$ 时优势恰为 $\sqrt{G-1}$),在 $p = 0$ 时归零。**这个截断就是零成功率问题的数学定位。**

#### 5.4 归一化本身引入的偏差

白化不是免费的。两处偏差值得单独记住:

* **除以 $\sigma$ 引入难度偏差。** Dr. GRPO 指出,mean-only 归一化(不除方差)才是无偏的策略梯度;除以 $\sigma$ 会按难度重新加权问题,系统性地给中等难度题更大的更新幅度。上面的表就是这个偏差的定量形式。它是 feature 还是 bug 取决于你要什么:想要自动课程,它是 feature;想要无偏梯度和可预测的 scaling,它是 bug。
* **除以 $|o|$ 引入长度偏差。** 原始 GRPO 按序列长度平均 token loss,这让长的错误回答每个 token 受到的惩罚更小,从而系统性地鼓励"错就错长一点"。DAPO 的 token-level loss(在整个 batch 的 token 上归一化,而非先按序列内平均)修掉了这一项。这是**长度爆炸**最常被忽略的直接来源——它不是模型在"学会深度思考",而是一个归一化 bug。

### 6. 为什么全对和全错的组无法提供有效相对优势

直接看代数。若组内所有 $r\_i$ 相等(全 0 或全 1),则 $\mu = r\_i$,于是分子 $r\_i - \mu = 0$ 对所有 $i$ 成立,$\sigma = 0$。无论实现是加 $\varepsilon$ 平滑还是显式置零,**该组对梯度的贡献严格为 0**。

这不是数值问题,是信息论问题:GRPO 的优势是**组内相对**的,一个没有内部差异的组不包含任何关于"什么更好"的信息。你花了 $G$ 次完整前向生成,换回来 0 bit。

定量地,一个组退化的概率是

\$$P(\text{degenerate}) = p^G + (1-p)^G\$$

| $p$  | $G=8$ | $G=16$ | $G=64$ |
| ---- | ----- | ------ | ------ |
| 0.5  | 0.8%  | 0.003% | \~0    |
| 0.2  | 17%   | 2.8%   | 0.001% |
| 0.05 | 66%   | 44%    | 3.8%   |
| 0.01 | 92%   | 85%    | 53%    |
| 0.95 | 66%   | 44%    | 3.8%   |

两个直接推论:

1. **有效 batch size 是一个随训练动态变化的隐变量。** 训练初期数据太难 → 大量全错组;训练后期数据被学会 → 大量全对组。两端都会让有效 batch 塌缩,表现为"loss 看着在动,但模型不再进步"。**必须把"非退化组比例"当成一等公民指标打点。**
2. **最优数据难度在 $p \approx 0.5$ 附近。** 结合 5.2 的权重表:$p=0.5$ 时组退化概率最低,且期望梯度幅度 $\propto \sqrt{p(1-p)}$ 最大。所以 GRPO 隐含地要求一个把数据维持在 50% 通过率附近的课程机制。这是"sweet spot"说法的来源。

### 7. Reward Sparsity 与采样效率:如何处理零成功率

先说清楚一件事:**零成功率不是算法能解决的问题**。$p=0$ 意味着策略的支撑集里没有正解,而策略梯度只能重新加权支撑集内的东西。你需要从**外部**注入一条成功轨迹。按侵入性从低到高:

**第 0 层:诊断。** 先用 pass@k(k=64 或 256,高温)测每道题的可解性,把数据分成"$p=0$"、"$0\<p<1$"、"$p=1$"三桶。前后两桶在当前阶段对 GRPO 是纯粹的算力浪费。这一步经常能直接找回 30%\~50% 的吞吐。

**第 1 层:采样层面(不改问题)**

* **Dynamic sampling(DAPO)**:过采样并丢弃退化组,持续补采直到 batch 填满非退化组。代价是每步的实际 rollout 数变多且不定,但有效 batch 恒定。这几乎是必选项。
* **提高 $G$**:把截断上限从 $\sqrt{G-1}$ 抬高,并把可用难度下界从 $1/G$ 推低。$G$ 从 8 到 64 会实质性地改变哪些题"可学"。
* **Clip-higher**:把上界裁剪 $\epsilon\_{\text{high\}}$ 放宽(比如 0.28),给低概率 token 留出被抬升的空间,抑制熵坍缩。熵一旦塌了,探索就停了,$p=0$ 的题永远不会变成 $p>0$。
* **温度与 top-p**:训练采样用高温、评测用低温。别用同一套解码参数。

**第 2 层:问题层面(改变 $p$ 而不改变任务)**

* **课程与难度分桶**:按实测 $\hat p$ 排课,维持 batch 的平均 $\hat p$ 在 0.3\~0.7。
* **提示注入 / 逆向课程**:把参考解的前 $k%$ 作为前缀塞进 prompt,让 $p$ 从 0 变成正数;随训练逐步减少 $k$。这是把 $p=0$ 的题**制造**成 $p>0$ 的题,最直接有效。
* **难度自适应权重**:对不同子任务按"剩余提升空间"加权,形成隐式课程(VPS 那条线的做法)。

**第 3 层:信号层面(把 1 bit 变成多 bit)**

* **分档奖励**:代码任务用**单元测试通过率**而非全通过与否;数学任务给格式分、给中间量正确性分。这是最便宜的稠密化,也是本文第 8\~10 节的主线。
* **过程奖励 / 子目标**:见第 8 节。
* **蒙特卡洛价值估计**:从推理链的中间状态继续 rollout,用后续成功率作为该步的价值,得到逐步优势(Math-Shepherd、VinePPO、VSRM 一类)。它把"全错"分解成"前 7 步其实有 40% 的成功前景,第 8 步归零"——即使最终没有一条完整正解,也能定位到断点。代价是 rollout 成本乘以链长。

**第 4 层:分布层面(引入外部轨迹)**

* **拒绝采样微调 / expert iteration 预热**:先用高温大量采样 + 验证器筛选出正解做 SFT,把 $p$ 从 0 抬到可 RL 的区间,再上 GRPO。这是最稳的工程路径,几乎所有严肃的 RLVR pipeline 都有这一步。
* **从更强模型蒸馏种子轨迹**:能力上限受教师限制,但对打开 $p=0$ 的题非常有效。

一个反直觉但重要的提醒:**不要为了消除全错组而无限降低数据难度**。如果所有题都是 $p \approx 0.9$,GRPO 会退化成一个"堵漏"机器——它会花全部预算在 5.2 表格里 $-9.95$ 那一栏,即惩罚偶发失误,而这与提升能力上限无关。

### 8. Outcome → Process:五条路径,以及为什么"可验证过程奖励"是当下的关键

PRM 的历史困境是:**要么贵,要么可被 hack**。

| 路径                    | 信号来源                                               | 成本       | 抗 hack                |
| --------------------- | -------------------------------------------------- | -------- | --------------------- |
| (a) 人工步骤标注            | 人类标注每步对错(PRM800K / Let's Verify Step by Step)      | 极高       | 高                     |
| (b) 蒙特卡洛价值估计          | 从中间状态续采,用后续成功率当步价值(Math-Shepherd / VinePPO / VSRM) | 高(算力)    | 中(继承 outcome 验证器的偏差)  |
| (c) 神经 PRM            | 用 (a) 或 (b) 的标签训一个打分模型                             | 中        | **低**(可被外推攻击)         |
| (d) LLM-as-judge 逐步评审 | 更强模型批改每一步                                          | 中        | **低**(风格、长度、自我偏爱可被利用) |
| (e) **规则式可验证过程奖励**    | 确定性程序检查每一步                                         | 低(一次性开发) | **高**                 |

(c) 和 (d) 的失效方式是同构的,而且有很干净的实证:有工作发现,把 rubric 分数直接喂进策略梯度,模型会学会过量生产 rubric 偏好的表面行为——在 AIME 2025 上表现为严重的自我纠错循环,近半数 rollout 反复重写和"再验证"中间步骤以抬高 rubric 分,常常不终止。这不是模型变笨了,而是**优化器忠实地找到了奖励函数的最大值,而那个最大值不在你想要的地方**。

#### 8.1 路径 (e):把 PRM 从"学出来的"变成"写出来的"

这是 ACL 2026 那条线索的核心主张。Verifiable Process Reward Model (VPRM) 的做法是:**在推理结构由领域规范预先给定的任务上,用确定性的规则验证器逐步检查中间结论**,完全不需要神经 judge。

那篇论文选的落地场景很有说服力:医学证据合成中的**偏倚风险评估**(risk-of-bias assessment)。理由是这个领域有现成的指南(如随机试验的 RoB 工具),它把评估拆成一串有明确定义的子判断,再用一棵**确定性的决策树**把子判断的组合映射到最终的 low / high / moderate 风险标签。于是每一步都有 ground truth 可比,最终标签也有——过程和结果**同时**可验证。作者报告 VPRM 的效果不仅超过纯结果奖励,也超过神经 PRM,并且在训练分布之外仍然成立(即不是在利用数据集的特定规律)。

把这个思路一般化,可验证过程奖励的构造模式是:

1. **找到任务里的显式结构**:领域指南、决策树、状态机、类型系统、代数规则、物理量纲。
2. **要求模型显式输出这个结构**:不是自由文本,而是带标记的中间量(`step_i: claim = value`)。
3. **对每个中间量写一个确定性检查器**:符号等价(SymPy)、量纲一致、数值区间、约束满足、状态转移合法性、与检索片段的可核对性。
4. **聚合**:$r = r\_{\text{outcome\}} + \lambda \sum\_i r\_i^{\text{step\}}$。

现成的实例已经不少:PRoSFI 让模型在自然语言推理之外并行输出**结构化形式中间量**,由定理证明器检查(避开了"让 7B 模型直接写完整 Lean 证明"这种不现实的要求);VPS 则处理"结构不是先天给定"的情况,用 SFT 先诱导出结构,再确定性地验证中间断言,并按剩余提升空间自适应加权子任务。

#### 8.2 设计原则:过程奖励做 shaping,结果奖励做锚

三条经验规则,理由都在第 4 节和第 5 节:

* **结果项必须保持主导** ($\lambda$ 小)。过程奖励是你对"好推理长什么样"的信念的编码,它必然不完备。让它主导优化,你就把不完备的信念变成了唯一目标。
* **优先用 potential-based shaping 形式**。若过程奖励能写成 $r\_i = \gamma\Phi(s\_{i+1}) - \Phi(s\_i)$ 的形式,理论上保证最优策略集不变——你只加速收敛,不改变目标。规则验证器往往能自然套进这个框架(把 $\Phi$ 取为"已满足的约束数")。
* **不奖励"步骤的存在",只奖励"步骤的正确"**。奖励步数、奖励"出现了反思词"、奖励长度,都是在直接教模型作弊。上面那个 48% 自我纠错循环的例子就是这么来的。

### 9. Reward Hacking 和错误验证器

把这一节当 checklist 用。RLVR 的失效基本都在这两张表里。

#### 9.1 策略攻击验证器

| 攻击    | 表现                                                               | 防御                                                   |
| ----- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| 测试泄漏  | 代码读取 test 文件、`__file__`、环境变量后硬编码答案                               | 测试与代码物理隔离,独立进程、独立目录、不传测试路径                           |
| 断言绕过  | 覆盖 `assert`、monkey-patch `unittest`、`sys.exit(0)`、修改 `pytest` 钩子 | 在受限解释器里跑;检查退出码**与**测试计数;禁止导入 `sys`/`os`(或白名单 import) |
| 平凡通过  | 用 `try/except: pass` 吞掉所有异常;返回硬编码常量恰好通过 3 个可见测试                  | held-out 测试;mutation testing(自动变异测试用例)               |
| 超时利用  | 死循环压 timeout,或利用"超时不算失败"的实现                                      | 超时显式记为 $r=0$;资源限额(CPU 时间、内存、进程数)                     |
| 格式钻空  | 一次输出多个 `\boxed{}` 覆盖多个可能答案;在推理里穷举                                | 只取最后一个/唯一一个;检测到多答案直接 $r=0$                           |
| 答案泄漏  | prompt 或 few-shot 里意外包含答案;数据集与预训练语料重叠                            | 去重、去污染、held-out 时间切片评测                               |
| 语言/退化 | 中英混杂、无意义重复、乱码但答案对                                                | 格式与语言一致性作为**门控**(不是加分项)                              |

#### 9.2 验证器自身出错

* **假阴性**(对答案被判错):等价形式未归一化。后果比想象严重——它给正确行为负梯度,而且这些负梯度出现在最难的题上(那里 $p$ 最小,失败权重虽小,但正确样本被误判成失败等于直接抹掉了唯一的正信号)。**上线前必须人工抽检 200 条被判错的样本。**
* **假阳性**(错答案被判对):子串匹配过宽、数值容差过大、多选题猜中。后果是模型学到捷径。
* **验证器覆盖不足**:3 个测试的"通过"和 30 个测试的"通过"是完全不同的奖励函数。稀疏的测试集直接定义了一个更宽的可行域,而 RL 一定会找到那个可行域里最便宜的点。

**元级防御**:定期用当前策略的输出去**攻击你自己的验证器**——把 $r=1$ 但人工判定为错的样本收集起来,它们就是下一轮验证器的测试集。这个循环和 RL 循环一样重要。

### 10. 用单元测试实现一个代码 RLVR Demo

配套代码见 `rlvr_grpo_demo.py`。它是一个自包含的、可读优先的最小实现,包含 RLVR 的全部关键部件:

````
任务集(prompt + 隐藏测试)
      ↓
  采样 G 条  ──────→  记录 old_logprobs(供 clip 使用)
      ↓
  抽取代码块(只取第一个 ``` 块)
      ↓
  沙箱执行(独立进程 / 超时 / 资源限额 / 测试与代码隔离)
      ↓
  reward = 通过测试比例  (可切二值)
      ↓
  组内白化 → 优势;丢弃退化组
      ↓
  token-level PPO 裁剪损失(clip-higher,可选 KL)
      ↓
  诊断打点:非退化组比例 / pass@1 / pass@k / 熵 / 长度
````

实现上真正容易出错、也真正决定成败的几点(代码里都有注释标出):

1. **log-prob 对齐**:`logits[:, :-1]` 对 `labels[:, 1:]`,并且**只在 completion token 上**计入损失。把 prompt token 算进去是最常见的 bug,表现为 loss 数值合理但模型不动。
2. **优势广播**:序列级优势要广播到该序列的每个 completion token,再按**全 batch token 数**归一化(而不是先按序列内平均)——见 5.4 的长度偏差。
3. **退化组必须显式过滤**,并把 `non_degenerate_ratio` 打点。这是最有信息量的单个指标。
4. **`old_logprobs` 必须在采样时冻结**。如果每个 batch 只做一次更新,ratio 恒为 1,裁剪毫无作用,你实际跑的是朴素 REINFORCE。要让 clip 起作用,需要内层多个 epoch。
5. **沙箱要当真做**:`subprocess` + `resource.setrlimit`(CPU 时间、地址空间、进程数)+ 临时目录 + 不传测试文件路径 + 超时杀进程组。demo 里的沙箱够用于本地实验,但**不足以运行不可信代码**——生产环境请用容器或 gVisor/Firecracker 级别的隔离。
6. **held-out 测试**:训练用一半测试,评测用另一半。两者分数的差距就是 reward hacking 的直接度量。

#### 关键代码片段(完整版见附件)

```python
def grpo_advantages(rewards, eps=1e-6, normalize_std=True):
    """组内白化。返回 (advantages, is_degenerate)。

    normalize_std=False 即 Dr. GRPO 的 mean-only 变体:
    去掉难度重加权,换取无偏的策略梯度。
    """
    r = torch.as_tensor(rewards, dtype=torch.float32)
    if r.max() - r.min() < eps:          # 全对或全错 → 0 bit 信息
        return torch.zeros_like(r), True
    adv = r - r.mean()
    if normalize_std:
        adv = adv / (r.std(unbiased=False) + eps)
    return adv, False
```

```python
def grpo_loss(logprobs, old_logprobs, adv, mask,
              clip_low=0.2, clip_high=0.28):
    """token-level 裁剪损失。clip_high > clip_low 即 DAPO 的 clip-higher,
    给低概率 token 留出被抬升的空间以抑制熵坍缩。"""
    ratio = torch.exp(logprobs - old_logprobs)            # [B, T]
    a = adv.unsqueeze(-1)                                 # [B, 1] → 广播
    unclipped = ratio * a
    clipped = torch.clamp(ratio, 1 - clip_low, 1 + clip_high) * a
    per_token = -torch.min(unclipped, clipped)
    # 关键:按全 batch 的有效 token 数归一化,而非先按序列内平均
    return (per_token * mask).sum() / mask.sum().clamp(min=1)
```

### 11. RLVR 能否扩展到不可验证任务

先给结论:**能扩展的程度,等于你能把"好"操作化到什么程度。这不是算法问题,是评价工程问题。** 把任务按可验证性排成一个谱:

| 层级    | 例子                             | 奖励构造               | 可靠性       |
| ----- | ------------------------------ | ------------------ | --------- |
| 完全可验证 | 数学答案、代码、形式证明                   | 执行 / 符号匹配          | 接近 1.0    |
| 结构可验证 | 按指南做的结构化判断、SQL、schema 填充、受约束生成 | 规则 + 决策树(VPRM)     | 高         |
| 可核对   | 知识问答、带引用的综述                    | 断言级溯源核验            | 中         |
| 可逆    | 翻译、摘要、代码↔测试                    | 往返一致性              | 中         |
| 弱可验证  | 有明确验收标准的写作                     | rubric 二元化 + judge | 低\~中      |
| 不可验证  | "写得动人"、开放对话质量                  | 偏好模型               | 由 RM 上限决定 |

几个可以真正落地的扩展手法:

**(a) 知识型任务 → 断言级可核对性。** 把回答分解成原子断言,每条断言必须能溯源到一个检索片段。奖励 = 可溯源断言比例 − 不可溯源断言的惩罚。这把"这个回答对吗"(不可验证)转化成了"这句话在这段证据里吗"(近似可验证,用 NLI 或字符串重叠判定)。局限:它奖励**可引用性**而非**正确性**,模型会学会只说容易溯源的话——一种保守化的 Goodhart。

**(b) 逆向任务生成。** 从已知答案构造问题,答案天然可验证。数据合成里非常有效,但会系统性地偏向"可逆的"问题分布,与真实查询分布逐渐脱节。

**(c) 往返一致性。** 翻译→回译→比对;代码→生成测试→跑测试;文章→出问答→答对率。这类奖励免标注、可扩展,失效模式是**模型可以同时学坏两端**(编码器和解码器约定一套私有映射,回译完美但翻译很差)。防御:两端至少一端冻结。

**(d) Rubric 二元化。** 把"这份报告好不好"拆成 20 条可判定的二元项("是否给出了置信区间"、"是否引用了原始数据源"、"是否标注了样本量")。规则能判的用规则,判不了的用 judge。核心是把 judge 的自由度压到最小——让它回答"这里有引用吗"而不是"这写得好吗"。**这就是把第 8 节的 VPRM 思路搬到开放任务上**:结构不是来自领域指南,而是来自你自己写的验收标准。

**(e) 约束满足作为门控而非目标。** 格式、长度、schema、禁用词这类硬约束应该做成**乘性门控**($r = \mathbb{1}\[\text{格式合法}] \cdot r\_{\text{quality\}}$),而不是加性奖励。加性会让模型用格式分补偿质量分——这是开放任务 reward hacking 最常见的入口。

#### 根本限制

三条,按不可绕过的程度排序:

1. **评价的可靠性是优化的上限。** 如果你的奖励函数在 15% 的样本上判断错误,RL 会精确地找到那 15%。这不能靠更好的 RL 算法解决——第 5 节的分析恰恰说明 GRPO 是个**极其高效的**奖励最大化器,它会以 $\sqrt{(1-p)/p}$ 的权重扑向任何罕见的高奖励行为,包括漏洞。**算法越强,验证器的漏洞越致命。**
2. **rubric 覆盖度决定了行为的多样性上限。** 你没写进 rubric 的好性质会被优化掉,因为它们不产生奖励却消耗概率质量。这在创造性任务上是致命的——已经有工作专门研究如何为创造性问题解决奖励"独特性"来对抗这一点。
3. **Goodhart 是结构性的,不是可修补的。** 只要奖励是目标的代理,足够强的优化就会分离两者。唯一的真实防御是**保持奖励函数的演化速度不低于策略的演化速度**——即把验证器/rubric 的迭代当成训练流程的一部分,而不是一次性的前置工作。

所以对"RLVR 能否扩展到开放任务"这个问题,我的回答是:能扩展到**你愿意为之写验收标准**的任务,不能扩展到你只能凭感觉判断的任务。而在写验收标准的过程中,你通常会发现自己其实并不清楚"好"是什么——这个发现本身,往往比训出来的模型更有价值。

### 附:实践 checklist

**开训前**

* \[ ] 用 pass@k(高温,k≥64)测出每道题的 $\hat p$,按难度分桶,丢掉 $\hat p \in {0, 1}$ 的题
* \[ ] 人工抽检 200 条 $r=0$ 的样本,估算验证器**假阴率**
* \[ ] 人工抽检 200 条 $r=1$ 的样本,估算验证器**假阳率**
* \[ ] 划出 held-out 测试集(代码)/ 等价形式测试集(数学),用于度量 hacking
* \[ ] 确认沙箱隔离:测试与代码分离、超时记为 0、资源限额、无网络

**训练中必打点**

* \[ ] `non_degenerate_group_ratio` — 最重要的单个指标,低于 0.5 就该动数据或 $G$
* \[ ] `pass@1` 与 `pass@k` **同时**看 — 前者升后者降 = 分布锐化而非能力提升
* \[ ] 策略熵 — 单调下降到接近 0 意味着探索已死
* \[ ] 平均生成长度 — 突然增长先怀疑归一化 bug(5.4),再怀疑"深度思考"
* \[ ] train reward 与 held-out reward 的**差值** — hacking 的直接度量
* \[ ] 各难度桶的 $\hat p$ 分布漂移 — 用于触发课程更新

**改动优先级**(投入产出比从高到低)

1. 修验证器(假阴/假阳)
2. 数据难度筛选 + dynamic sampling
3. token-level loss(去长度偏差)+ clip-higher
4. 增大 $G$
5. 分档奖励(测试通过率)
6. 可验证过程奖励
7. 蒙特卡洛过程价值估计
8. 调 $\beta$ / 去掉 reference KL(注意这是天花板旋钮,不是稳定性旋钮)
